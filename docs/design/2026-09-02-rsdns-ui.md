# rsdns 内置 UI：`metrics` → `ui` 配置与内嵌 HTML 仪表盘

> 2026-09-02 | 提案

## 1. 动机

当前 `metrics:` 配置段启动一个 Prometheus 文本格式的 HTTP 端点，只服务于
Prometheus 采集器：

- 配置段名为 `metrics`，端点固定为 `/metrics`（`path` 可配），与“Prometheus
  指标端点”的职责绑定。
- 端点输出原始文本，对人类不友好：手机、无 Prometheus 的环境下无法快速查看
  服务健康状况（内存、缓存等）。
- 需要一个手机友好、开箱即用的状态页；同时保留 `/metrics` 文本供
  Prometheus 采集。

本次把 `metrics:` 配置段改名为 `ui:`，HTTP 服务只暴露 `/` 与 `/metrics` 两个
路径：`/` 返回**内嵌到二进制**的 HTML 仪表盘（手机友好、彩色圆角框图、人类可读
指标），`/metrics` 保留 Prometheus 文本格式。`path` 配置项移除。

## 2. 目标 / 非目标

### 目标

- 配置段 `metrics:` → `ui:`，`path` 配置移除；未配置 `ui:` 时不监听（指标仍
  在内存计数，与现状一致）。
- HTTP 服务只暴露两个路径：`/`（HTML 仪表盘）与 `/metrics`（Prometheus 文本，
  与现状输出一致）。其余路径 404。
- HTML 内嵌进二进制文件（`include_str!`），无运行时外部文件依赖。
- 仪表盘手机友好：响应式布局、常用模块列出、彩色圆角框图（card）、内部数据
  人类友好可读（如字节 → KB/MB/GB）。
- 至少展示**内存**与**缓存**指标；其余常用指标按“少而精”原则只列高频项。

### 非目标

- 不新增第三方依赖（`prometheus` crate、前端框架、JS 图表库均不引入）。
- 不做 `/metrics` 文本格式之外的 Prometheus 语义变更（`MetricsRegistry` 不动）。
- 不添加测试（用户明确要求）。
- 不引入实时推送/WebSocket：仪表盘用页面内定时 `fetch('/metrics')` 刷新。
- 不改动任何查询管线 / rules / cache / upstream 逻辑。

## 3. 方案

### 3.1 配置段改名 `metrics:` → `ui:`

```yaml
# 之前
metrics:
  bind: "0.0.0.0:9153"
  path: /metrics

# 之后
ui:
  bind: "127.0.0.1:8153"
```

- `UiConfig { bind: String }`：只保留 `bind`（默认 `"127.0.0.1:8153"`，仅监听
  回环，UI/指标不暴露到公网）。`path` 删除。
- 旧 `metrics:` 段不再被读取（落入 `plugin_sections` 但不被消费，行为与任意未
  知段一致，不报错）。仓库配置一贯不承诺向后兼容（见
  `2026-08-20-rsdns-plugins.md` §11 风险）。
- 解析失败（`bind` 非法）沿用现状：`warn` 并禁用该段，服务继续启动。

### 3.2 模块重命名与文件移动

- `src/plugins/metrics.rs` → `src/plugins/ui.rs`（`git mv`），模块名与配置段
  一致。
- `src/plugins/mod.rs`：`pub mod metrics;` → `pub mod ui;`。
- `src/main.rs`：三处调用同步改为 `plugins::ui::*`：
  - `config(&config)` → 读 `ui:` 段；
  - `bind_listener(&cfg)`；
  - `serve_ui(listener, cfg, registry)`（由 `serve_metrics` 改名）。
- 配置解析测试（`src/config.rs::test_parse_array_config` 断言
  `plugin_sections.contains_key("metrics")`）改为 `"ui"`，示例 YAML 同步改
  为 `ui:`（见 §5）。
- `MetricsRegistry`（`src/metrics.rs`）不变；`ui.rs` 继续消费它。

### 3.3 HTTP 路由：`/` 与 `/metrics`

`serve_ui` 的 handler 按 `req.uri().path()` 分派：

| 路径 | 响应 |
|------|------|
| `/` | `200`，`Content-Type: text/html; charset=utf-8`，内嵌 HTML（`include_str!("ui.html")`） |
| `/metrics` | `200`，`text/plain; version=0.0.4; charset=utf-8`，`registry.encode_text()`（与现状一致） |
| 其他 | `404` `not found` |

`path` 配置删除后，`/metrics` 固定（这也符合 Prometheus 惯例与
`prometheus.io` 默认抓取路径）。

### 3.4 内嵌 HTML：`src/plugins/ui.html`

- 用 `include_str!("ui.html")` 编译进二进制；构建期不校验、无需外部资源
  （无 CDN、无网络字体）。
- 单文件、零依赖：一个 `<style>`、一个 `<script>`（原生 JS，无框架）。
- **数据来源**：`fetch('/metrics')` 拉 Prometheus 文本 → 前端解析
  `name{labels} value` 行 → 渲染。不引入 JSON 接口，复用现有
  `/metrics` 端点。
- **手机友好**：`<meta name="viewport">` + flex/grid 响应式布局，卡片在窄屏
  单列、宽屏多列。
- **彩色圆角框图**：每项指标一张 card（圆角、白底、左侧色条/边框色区分），
  含标题、人类可读数值、描述。
- **人类友好数值**：字节类（jemalloc `*_bytes`）格式化为 KB/MB/GB；计数类
  大数用千分位/`k/M` 缩写。
- **模块筛选（少而精）**：只渲染固定白名单模块，未注册的指标不显示：

| 模块 | 指标 |
|------|------|
| 内存 | `rsdns_jemalloc_allocated_bytes`、`active`、`resident`、`mapped`（显示为 MB/GB 与占比） |
| 缓存 | `rsdns_cache_entries`、`rsdns_cache_lookup_total{fresh/miss}` |
| 查询 | `rsdns_logs_queries_total{proto}`、`rsdns_rules_evaluated_total`、`rsdns_rules_matched_total{action}`、`rsdns_upstream_query_total`、`rsdns_upstream_error_total`、`rsdns_upstream_pool_connections` |
| 组 | `rsdns_groups_entries{group}` |

  > 选型说明：内存（`jemalloc`，默认 feature）与缓存（`cache`）为最低要求；
  > 查询/组按“常用高频”补充，控制模块数量。白名单集中在 HTML 顶部常量数组，
  > 便于增删。
- **刷新**：`setInterval` 每 3s 拉取一次；拉取失败保留上次数据并在页脚提示
  “更新失败”。页面加载即拉一次。

### 3.5 主流程改动（`src/main.rs`）

`run()` 中：

```rust
let ui_listener = if let Some(cfg) = plugins::ui::config(&config) {
    Some((plugins::ui::bind_listener(&cfg).await?, cfg))
} else {
    None
};
// ...
if let Some((listener, cfg)) = ui_listener {
    let registry = metrics.clone();
    tasks.spawn(async move {
        if let Err(e) = plugins::ui::serve_ui(listener, cfg, registry).await {
            error!("ui server failed: {}", e);
        }
    });
}
```

- 绑定仍与 DNS 监听并列：任一绑定失败 → 整体失败退出（现状语义保持）。
- `jemalloc` 的 `spawn_refresh` 周期刷新内存 gauge 不变（无论是否配置 `ui:`）。

## 4. 配置变更影响

| 位置 | 变更 |
|------|------|
| `src/plugins/metrics.rs` | 文件重命名 → `src/plugins/ui.rs`；`MetricsConfig` → `UiConfig { bind }`（删 `path` 与 `default_metrics_path`）；`config()` 读 `ui:`；`serve_metrics` → `serve_ui`（`/` + `/metrics` 路由） |
| `src/plugins/ui.html` | 新增内嵌 HTML（`include_str!`） |
| `src/plugins/mod.rs` | `pub mod metrics;` → `pub mod ui;` |
| `src/main.rs` | `plugins::metrics::*` → `plugins::ui::*`；`metrics_listener` → `ui_listener` |
| `src/config.rs` | 单测 `contains_key("metrics")` → `contains_key("ui")` |
| `example/rsdns-all-example.yaml` | `metrics:` 段 → `ui:`（删 `path`），注释说明 `/` 与 `/metrics` |
| `README.md` / `README.en.md` | `metrics` 描述更新为 `ui`（内置状态页 + `/metrics`） |
| `Cargo.toml` | 无改动（无新增依赖） |

## 5. 测试

用户明确要求**不添加测试**。改动后仅需通过 `make ci`（fmt + clippy + check +
test）确保现有单测（含改名的配置断言）通过。

## 6. 兼容性

- 配置段从 `metrics:` 改为 `ui:`，旧 `metrics:` 忽略（不报错、不兼容）。
- `/metrics` 文本格式与输出完全不变，Prometheus 采集无缝迁移。
- 查询管线、rules、cache、upstream 零改动。

## 7. 风险与权衡

- **前端解析 Prometheus 文本**：行格式简单（`name{labels} value`），手工解析
  约 30 行；若未来引入 Histogram（`_bucket`/`_sum`/`_count`）需扩展解析，但当前
  注册表只有 counter/gauge，无此风险。
- **`include_str!` 路径**：HTML 放在 `src/plugins/` 下，`include_str!` 相对当前
  文件路径，无构建脚本改动。
- **旧 `metrics:` 段静默忽略**：与仓库“配置不向后兼容”惯例一致；如需过渡可在
  后续版本加别名。
